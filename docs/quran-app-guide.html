Project guide

Quran App Guide

What the app does, feature by feature, followed by the build plan with resources for each step.

1
Overview

An offline-first Quran app for reading, listening, and sharing recitations. It is built with Expo React Native, one codebase for Android, iOS, and web.

  • Downloads for offline use work on Android and iOS only. The web version is online only.
  • Desktop apps for Windows and Mac are parked for now.
  • Typing practice comes later. It has a tab placeholder but is not part of the first release.
  • Publishing waits until written permission is received for the audio and text sources. Until then, we build without publishing.

2
Quran reader

The reader is the main screen. It has a top bar, a scrolling unit card in the middle, and an audio bar at the bottom.

Top bar

  • Unit picker: verse, page, juz, ruku, or surah.
  • Display mode picker (see below).
  • English toggle.

Unit card

The middle area shows the current unit. A unit is the range of verses picked in the unit picker. Swiping moves to the next or previous unit of the selected size.

Display modes

  • Mushaf: lines appear as they do in a printed Madani Mushaf, using the Mushaf layout data.
  • Under the unit: the Arabic flows like a printed page, and the English for each verse is listed below it in order. This is the default.
  • Inline: the Arabic flows, and each verse's English appears right after its end marker.
  • Arabic only: no English.
  • English only: no Arabic.

Verses flow across lines, so a verse can start in the middle of a line and continue on the next. Each word is a font glyph, with tajweed colors. Tapping a word selects its verse.

Verse header

Each verse has a header with the verse number and actions: play from this verse, set as default, and report.

Audio bar

  • Previous, play/pause, and next.
  • Progress bar, which can also be used to seek.
  • Loop button: loops the current unit. There is one loop button and no repeat count.
  • Auto-advance toggle: on by default. When on, playback moves to the next unit when the current one ends.
  • Source picker: chooses which recording plays.
  • No speed control.

Playback continues when the phone is locked (background playback).

Verse data comes from quran.json: 6,236 verses with ids 1 to 6236, each with surah, ayah, juz, Arabic, and English. The Mushaf layout data gives the lines for each page.

3
Audio sources and defaults

Every unit can have a default recording. Defaults are saved per user.

  • Most specific wins. A verse default beats a page default, which beats a juz default.
  • Session choice. Picking a track for current playback overrides the defaults until the app closes.
  • Track as default. A track can be set as the default for its whole verse range. This wins over narrower defaults for those verses only.
  • Replacing a default. Setting a new default for the same range replaces the old one.
  • Offline fallback. If the default is not downloaded, the app plays the nearest downloaded source and shows a short message. The saved default does not change.

4
Hub

The Hub is the second tab. It opens on Search, with Library second.

  • Search: a Recordings / Playlists switch. Recordings can be searched by title, reciter, riwayat, style, and verse range. Playlists are searched by title.
  • Library: downloads, playlists, clips, and my uploads.
  • Offline: search shows a "No internet" message. Library still works for downloaded items.

Search sort options come later.

5
Recordings and upload

A recording is one uploaded recitation: a whole audio file, covering a range of verses.

Recording fields

  • Title: required.
  • Reciter: who recited it.
  • Riwayat: optional. Hafs an Asim or Warsh an Nafi.
  • Style: optional. Murattal, Mujawwad, or Mu'allim.
  • Verse range: first and last verse.
  • Status: draft (only the uploader sees it), unlisted (opens by link, not in search), or published (in search and by link).

Upload flow

  1. Pick an audio file from the phone.
  2. Fill in the details.
  3. Mark each verse on the timeline by tapping where it starts.
  4. Fix marks by dragging them, or set exact times with the time picker.
  5. Review, then publish.

The time picker uses scroll wheels. Hours and minutes appear only when the track is long enough. Seconds and hundredths always appear. Times are stored as whole hundredths of a second.

A rights notice sits above the upload button. A rights checkbox must be ticked before publishing.

Recording page

Shows the header, the verse marks, a report button, and a set-as-default button.

Deleting a recording

When a recording is deleted, its row and its audio files are removed. A recording is deleted when its uploader deletes it, or after reports lead to removal.

6
Playlists

A playlist is a named list of items that play one after another, like a Spotify playlist.

  • Each item is either a whole recording or a clip. A clip is a range of verses from a recording.
  • A playlist can mix whole recordings and clips.
  • Playlists play in order, with auto-advance.
  • Status: private (only the owner sees it, the default), unlisted (opens by link), or published (in search).
  • No collaborative playlists.
If a recording is deleted, items from it stay in the playlist and show "removed recording." Clips keep their verse range in the note.

7
Reports and moderation

  • Every recording has a report button.
  • A report has an optional message, up to 500 characters.
  • The same user can report the same recording more than once. Rate limiting controls how often.
  • A report keeps the reporter and the recording. If either is deleted, its link is cleared. The report is removed once both links are cleared.

8
Profiles and follows

  • Profile fields: one name field, an optional country, a setting for whether the following list is visible, and a setting to hide the profile from search.
  • Not included: profile picture, age, and gender.
  • Following list: visible only if the user allows it.
  • Followers: never shown to anyone.
  • Hidden profiles: show a default name. The name is not decided yet.
  • Follow: instant, with no request step. One follow per pair of users. Following yourself is not allowed.

9
Login and accounts

Login uses email and a one-time code (OTP), through Better Auth, running on our own database. The app stores the user's email.

When an account is deleted

  • The profile is removed.
  • Follows and unit defaults are removed.
  • Recordings and playlists stay, with the uploader cleared.
  • Reports stay, with the reporter cleared.

When a reciter is deleted

The reciter is removed, but their recordings stay, with the reciter cleared.

10
Data model at a glance

  • Lists picked from, not added to: riwayat and style (enums).
  • People: profiles, follows, reciters.
  • Recordings: recordings, recording_files, verse_marks, reports.
  • Playlists: clips, playlists, playlist_items.
  • Defaults: unit_defaults.
Units are not stored in the database. They are built in the app from quran.json. Tags, tag links, and recording sources were dropped from the plan.
